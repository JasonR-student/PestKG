04

设计系统补全

现有 tokens.css 只定义了颜色，且组件中仍有 20+ 处硬编码。建议将 token 扩展为三层结构：原始值（Primitive）→ 语义角色（Semantic）→ 组件/节点类型（Component），所有组件只允许引用语义层及以上。

Token 三层模型

① Primitive 原始值

按色阶/刻度命名，不绑定用途，如 --green-700、--space-2。只在本层出现具体 hex/px。

② Semantic 语义角色

表达"是什么角色"，如 --color-primary、--color-text-muted、--radius-panel，组件主要引用本层。

③ Component / Type

节点类型等领域语义，如 --node-product、--node-ingredient，供图谱、图例、表格徽章共用。

色板（含节点类型语义色）

下列颜色在保留现有视觉的前提下统一归源；仅产品色由 #c06144 收敛到 --coral #b9583d、靶标色收敛到 --amber，其余保持不变。

落地方式

节点色单一来源

新增 shared/lib/node-theme.ts，导出 NODE_COLOR: Record<NodeType,string> 与类型中文/英文名；GraphCanvas、图例、表格徽章统一引用，避免颜色多处维护。Cytoscape 不直接读 CSS 变量，由该模块作为与 token 同步的唯一来源。

渐进替换，不推倒重来

阶段三按 CSS 文件逐个把硬编码替换为 token（#17493f→var(--green-700)、#e8ecea→var(--border) 等），每次替换后跑构建与 E2E；可加一条 lint 规则（stylelint/自定义脚本）禁止样式文件新增 hex。

06

图谱画布重构（核心）

GraphCanvas 是门户信息密度最高、复用最多（探索页 + 实体页）的组件，当前 4 项 P1 问题集中于此。重构目标：一个持久实例、数据增量同步、按规模选布局、补齐图例与关系语义、全屏真实可用。

重构要点总览

单实例 + 增量同步

Cytoscape 实例只创建一次；数据变化用 add/remove diff，语言变化只更新标签。缩放、平移位置不再丢失。

按规模选布局

小图 cose、大图 concentric（围绕中心节点、确定性、无长计算）；仅在节点集合变化时重布局。

语义可读

左下角类型图例（可点击高亮）、边显示关系谓词（小图常驻 / 大图悬停）、中心节点环形高亮。

① 单实例与增量同步

将"创建实例"与"同步数据"拆为两个 effect，并把同步逻辑抽到可单测的 useGraphSync hook；组件接收新增的 centerId prop（探索页传选中记录的 use_id，实体页传当前 nodeId）。

// 数据变化：diff，而非 destroy/recreate function syncGraph(cy, graph, centerId) { cy.startBatch() const nextNodes = new Map(graph.nodes.map(n => [n.id, n])) cy.nodes().filter(n => !nextNodes.has(n.id())).remove() cy.edges().filter(e => !graph.edges.some(x => x.id === e.id())).remove() for (const node of graph.nodes) { const el = cy.getElementById(node.id) const data = buildNodeData(node, centerId) el.length ? el.data(data) : cy.add({ group: 'nodes', data }) } for (const edge of graph.edges) { if (!cy.getElementById(edge.id).length) cy.add({ group: 'edges', data: buildEdgeData(edge) }) } cy.endBatch() if (needsLayout(cy, graph)) runLayout(cy, centerId) // 仅结构变化时 else cy.resize() } // 语言变化：只改标签，不碰结构 function applyLanguage(cy, graph, language) { cy.nodes().forEach(n => n.data('label', labelFor(n, graph, language))) cy.style().update() }

② 布局策略（解决深度 2 卡顿）

节点规模布局理由
1–3grid最简单、确定，与现状一致。
4–80cose（animate:false）力导向美观，规模可控时计算快。
> 80concentric以中心节点为同心圆分层，确定性强、复杂度低，近 1000 节点也能快速稳定；零新增依赖。

重布局只在首次渲染或节点集合发生增删时触发；切换选中行若节点集合不变则保持视口。若后续仍希望大图拥有力导向观感，可评估将 cose-bilkent（约百余 KB）动态 import 进图谱异步 chunk，但需先验证 500 KiB chunk 门，默认方案不引入新依赖。

③ 图例、关系标签、中心节点

类型图例（左下角）

  • 只列出当前图中实际出现的节点类型，圆点色取自 node-theme.ts。
  • 点击某类型：其余节点淡化（opacity 0.25），再次点击恢复——真实过滤交互。
  • 图例与右下角节点计数、控件不重叠。

边的关系谓词

  • 节点 ≤ 20：边标签常驻（9px、灰色、text-background 白底）。
  • 大图：悬停某条边时显示谓词，避免标签铺满。
  • 与中心节点直接相连的边，谓词常驻。

中心节点高亮

  • 中心节点加 .center class：尺寸加大（34px）、双层环形描边、标签始终常驻。
  • 点击中心节点不重复跳转自身；其余节点 tap 仍进入实体页。

视图控件

  • 保留滚轮 / 双指缩放；新增"复位视图（fit）"按钮。
  • 全屏按钮接入 Fullscreen API（见下），图标随状态在放大/缩小间切换。

全局搜索

顶栏全局搜索是跨页面的主入口，当前仅支持鼠标、承诺了 listbox 语义却无键盘行为。优化后达到"可纯键盘完成一次检索"，并补齐 ARIA 与外部点击关闭。

交互规格

行为规格
输入防抖在现有 useDeferredValue 基础上增加 300ms debounce（推荐抽 useDebouncedValue hook），停止输入后才发请求；快速输入不产生请求风暴。
↑ / ↓ 方向键在结果间移动高亮（activeIndex），高亮项滚动到可见；鼠标悬停与键盘高亮保持同一状态。
Enter有高亮项 → 打开该实体；无高亮项（或未展开）→ 跳转 /explore?query={词} 查看完整结果集。
Esc收起结果列表并保留输入框文字；再次输入可重新展开。
点击外部通过容器 ref 监听 mousedown，点到搜索框以外区域收起结果。
输入提示输入 1 个字符时提示"至少输入 2 个字符"；加载中、无结果文案走 i18n，不再硬编码英文。

ARIA 规范

角色与属性

  • 容器 role="listbox"，每条结果 role="option"。
  • 输入框 aria-controls 指向列表、aria-activedescendant 指向高亮项 id、aria-expanded 表示展开状态。
  • 高亮项 aria-selected="true"。

键盘逻辑示例

const onKeyDown = (e) => { const n = data.length if (e.key === 'ArrowDown') setActive(i => (i + 1) % n) if (e.key === 'ArrowUp') setActive(i => (i - 1 + n) % n) if (e.key === 'Enter') active != null ? open(data[active]) : goExplore(query) if (e.key === 'Escape') setOpen(false) }

搜索结果面板层级使用 --z-menu:60，需高于顶栏（30）与侧边栏（40），避免被遮挡；移动端面板宽度 min(560px,82vw) 已在现有样式中，保持不变。

08

状态体系

按概念文档要求，每个数据视图都需覆盖加载、空、错误、阻断、已填充五类状态，并在服务整体不可用时提供全局降级。当前骨架通用、错误无码无重试、空态分散、缺全局降级与 ErrorBoundary。

请求状态机

统一组件接口

LoadingState

提供骨架"原语"（标题块 / 工具条 / 面板 / 表格行），由各页面按自身布局组合页面级骨架（如探索页 = 筛选带骨架 + 表格行骨架 + 图面板骨架），数据到达时无大幅位移。

ErrorState

显示三部分：稳定错误码（等宽小字，如 entity_not_found）+ 面向用户的 message + "重试"按钮（接 query.refetch）。

EmptyState

统一空态：说明"当前 Release 与筛选条件没有匹配的已发布记录"，并提供"重置筛选"按钮（传入 onReset 时显示）。

全局降级与异常兜底

场景处理
Release 列表加载中AppShell 渲染整页启动骨架，而非让各页面各自等待。
503 无可用 Release全局 ServiceUnavailable 页：区分 no_release_available（当前没有已验证版本）与网络错误，说明原因并提供"重试"；不再落到无信息的错误框。
渲染期异常新增 AppErrorBoundary 包裹主区域：捕获后显示友好兜底 + "刷新页面"，可在 componentDidCatch 预留上报钩子，杜绝整页白屏。
实体 404识别 code === 'entity_not_found'，显示"该实体在此数据版本中不存在（可能已随版本更新变更）"，附"返回研究概览"。

重试策略修正

// main.tsx：仅对可恢复的 5xx / 网络错误重试一次 retry: (failureCount, error) => (error.status >= 500 || error.status === 0) && failureCount < 1 // 404 / 422 / 409 等确定性错误立即返回，不再白等一次

国际化与数字格式

门户定位为中英双语研究工作台，但 i18n 目前只覆盖导航，页面文案以三元表达式散落在组件中；数字格式也不跟随界面语言。目标：可见文案 100% 走 i18n，数字/日期随界面语言，标识符永不翻译。

文案归位

词条组织

  • 按功能分区扩展资源：overview / explore / compare / entity / downloads / methods，与导航、common 并列。
  • 当前规模可继续维护在 i18n.ts 单文件；词条超过数百条时再拆 locales/zh/*.json 并按路由懒加载。
  • 组件内一律 t('explore.title')，删除 english ? … : …。

不翻译的内容

  • 节点 ID、Release ID、source_record_id、官方字段值、来源 URL。
  • 技术谓词名（exactMatch / lexicalAlignment）保留原文。
  • 较长英文标签允许换行，不靠缩小字号强行单行。

词条结构示例

zh: { overview: { title:'多国农药登记知识图谱', metrics:{ jurisdictions:'司法辖区', sourceRecords:'源记录' } }, explore: { title:'登记使用数据探索', actions:{ export:'导出筛选 CSV' } } } en: { overview: { title:'Multicountry pesticide registration knowledge graph', metrics:{ jurisdictions:'Jurisdictions', sourceRecords:'Source records' } }, explore: { title:'Registration-use explorer', actions:{ export:'Export filtered CSV' } } }

数字与日期随语言

格式化函数接收显式 locale（en→'en-US'，zh→'zh-CN'），由调用方从 i18n.language 传入，确保英文界面一律 K/M、中文界面一律万/亿。

函数调整
formatCompact(v, locale)en-US：974K / 1.2M；zh-CN：97.4万 / 120万，与界面语言严格一致。
formatInteger(v, locale)分隔符随 locale（en 逗号 / zh 可不用或按习惯），数字统一 font-variant-numeric: tabular-nums。
日期Release 发布日、截止日、登记/到期日期使用 Intl.DateTimeFormat(locale)；原始 ISO 日期在详情中保留可核对。

筛选工作台（Explore）

保留现有"草稿（draft）→ 应用（applied）"的两段式筛选（避免边输边查），但要让全部已应用筛选可被 URL 完整表达，使刷新、分享、从搜索/地图跳入都能复现分析现场。

URL 状态双向同步

进入 URL 的字段

  • jurisdiction · query · product · active_ingredient · crop · target · formulation（registration_status / pairing_status 同理）。
  • 地图、国家排名、全局搜索 Enter 均通过这些参数落地（如 ?jurisdiction=AU、?query=glyphosate）。

不进入 URL 的字段

  • 分页游标 cursor：与 Release、筛选指纹绑定，不可分享、不可跨版本复用，仅存在于查询状态。
  • 当前选中行：可选（use_id 较长），首条记录自动选中即可满足图谱展示。

序列化函数（可单测）

// filters → URL const toParams = (f) => { const p = new URLSearchParams() if (f.jurisdictions[0]) p.set('jurisdiction', f.jurisdictions[0]) for (const [k, v] of Object.entries(f)) if (k !== 'jurisdictions' && v) p.set(k, v) return p } // URL → applied filters（初始化 & 分享链接落地） const fromParams = (p) => ({ jurisdictions: p.get('jurisdiction') ? [p.get('jurisdiction')] : [], query: p.get('query') ?? '', active_ingredient: p.get('active_ingredient') ?? '', crop: p.get('crop') ?? '', /* …其余字段同理 */ })

应用筛选时用 setSearchParams(toParams(draft))；初始化 applied filters 改为 fromParams(searchParams)。这样"地图点击 → 探索页 → 调整筛选 → 复制链接给同事"全链路状态一致，且这两个纯函数可直接写单元测试。

性能优化

现有代码分割与按需加载已打下好基础，进一步的优化以"预测下一步操作并预取"和"消除不必要的加载"为主，不增加复杂度。

手段方案优先级
交互预取鼠标悬停/聚焦国家排名行或地图国家时，queryClient.prefetchInfiniteQuery 该辖区登记用途首屏；点击即出结果。预取在空闲时进行、可取消。P2
查询缓存分级Release 列表/ Schema 变化极少 → staleTime: 10min+；stats 概览沿用 60s；搜索结果短缓存。按查询单独设置，避免统一过期。P2
图片懒加载方法页两张研究图加 loading="lazy" decoding="async"；首屏不携带非首屏图片字节。P2
图谱 chunk 校验确认 Cytoscape 经动态 import 形成独立异步 chunk（必要时在 Rolldown 分组中显式命名 cytoscape），与 ECharts chunk 互不影响，全部 ≤ 500 KiB。P2
入口预加载index.html 对首屏关键 chunk 使用 modulepreload（Vite 通常自动注入，构建后核对），favicon 与图标 SVG 保持现状。P2
大数据布局深度 2 大图改用 concentric（见第 6 节），从根本上消除布局长计算；无需 Web Worker 即可满足当前规模。P1

登记用途总量虽达 82 万，但采用游标分页 + 每页 20 条，DOM 中始终只有少量行，不需要引入虚拟滚动；避免为不存在的性能问题增加依赖。

部署与 Web 服务器

前端容器（apps/web/nginx.conf）只负责静态资源；生产入口由 Caddy（infra/caddy）承担 TLS 与 /api、/downloads 反向代理。优化集中在缓存分层、压缩、安全响应头三处。

缓存策略（关键）

资源当前建议
Vite hash 资源（/assets/*）7d + immutablepublic, max-age=31536000, immutable（文件名含内容 hash，可永久缓存）。
index.html默认（可能被缓存）Cache-Control: no-cache，每次校验；发版后用户立即拿到新 html + 新 hash 资源，消除"旧版白屏"。
/research、favicon 等7d中等时长（如 7d）即可，不带 immutable。

建议 nginx.conf（静态容器内）

gzip on; gzip_types text/css application/javascript image/svg+xml application/json; gzip_min_length 1024; server { listen 80; server_name _; root /usr/share/nginx/html; index index.html; location = /healthz { return 200 "ok\n"; add_header Content-Type text/plain; } # hash 资源：永久强缓存 location /assets/ { expires 1y; add_header Cache-Control "public, immutable"; } # 入口 html：每次校验 location = /index.html { add_header Cache-Control "no-cache"; } location / { try_files $uri $uri/ /index.html; } add_header X-Content-Type-Options nosniff always; add_header X-Frame-Options "DENY" always; add_header Referrer-Policy strict-origin-when-cross-origin always; add_header Permissions-Policy "geolocation=(), microphone=()" always; # CSP 按实际内联/外部资源收紧；style 需允许 'unsafe-inline'（框架样式） add_header Content-Security-Policy "default-src 'self'; img-src 'self' data:; script-src 'self'; style-src 'self' 'unsafe-inline'; connect-src 'self'; frame-ancestors 'none'" always; }

CSP 上线前需在真实构建上验证（确认无被拦截的脚本/样式/连接），先以 Content-Security-Policy-Report-Only 观察一轮再转强制；Caddy 层继续负责 TLS（www.pestkg.samlab.cn）、/api 与 /downloads 反代，职责不与静态容器混淆。
